# Briefed Architecture

## Overview

Briefed is a Go monolith with two execution paths:

- A Chi HTTP server handles onboarding, sessions, feed discovery, follows, contributions, and personalized posts.
- A background scraper periodically fetches shared RSS/Atom feeds and stores new articles.

Both paths use the sqlc-generated database package and the same PostgreSQL database.

```text
Browser / HTMX
      |
      v
Chi handlers -----> sqlc queries -----> PostgreSQL
      |                                      ^
      v                                      |
shared feed parser <----- background scraper-+
```

## Packages

- `internal/api` contains routes, handlers, cookie authentication, request helpers, and response models.
- `internal/database` is generated by sqlc and must not be edited manually.
- `internal/feedparser` fetches and parses both RSS and Atom.
- `internal/scrapper` selects the least-recently-fetched feeds and stores their articles.
- `sql/schema` contains clean goose migrations for a new database.
- `sql/queries` contains the handwritten SQL used by sqlc.

Manual dependency injection is kept intentionally small. `main.go` creates the SQL connection, generated query object, API configuration, router, and scraper.

## Request flow

Public onboarding:

```text
GET categories
      |
GET feeds filtered by selected categories
      |
POST registration with category_ids and feed_ids
      |
user + interests + follows + session created in one transaction
```

Authenticated requests use the `briefed_session` HTTP-only cookie. The middleware looks up a non-expired session and passes the associated user to the handler.

## Shared feeds

A feed has a nullable `submitted_by` field for attribution only. It is not owned by that user.

- Any user can follow an existing feed.
- A contributed URL is fetched and parsed before insertion.
- RSS and Atom titles are extracted from the document.
- New feeds receive the selected category relationships.
- The submitter automatically follows the feed.
- Submitting an existing URL simply follows the existing feed.
- Normal users unfollow shared feeds rather than deleting them.

## Personalized posts

Personalization is subscription-based. The posts query joins `posts` to `feed_follows` and filters by the authenticated user. Interests are used only for discovering feeds.

Results are ordered by `published_at DESC` and use `limit`/`offset` pagination.

## Scraper

The scraper runs on a ticker and:

1. Selects a small batch ordered by `last_fetched_at ASC NULLS FIRST`.
2. Fetches each feed concurrently.
3. Parses RSS or Atom through `internal/feedparser`.
4. Marks the feed as fetched after the attempt.
5. Inserts valid articles.
6. Relies on `ON CONFLICT (url) DO NOTHING` for duplicate prevention.

This project intentionally does not include distributed leases, conditional requests, exponential backoff, or multi-instance coordination.

## Authentication

Passwords are hashed with bcrypt. Registration and login create a random 30-day session stored in PostgreSQL and returned as an HTTP-only, SameSite=Lax cookie. Logout deletes the database session and clears the cookie.

Email verification, password recovery, and account administration are outside the current scope.
